# OfferProof 제품 계약

## 한 줄 정의

사용자가 제공한 구인 제안에서 확인이 필요한 신호를 원문 근거와 함께 표시하고, 공식 안내에 맞춘 다음 확인 단계를 만드는 WebMCP 협업 보드입니다. 사기 또는 안전 여부를 확정하지 않습니다.

## 대상 사용자

낯선 채용 제안, 재택근무 제안, 메신저 구인 연락을 받고 무엇부터 확인해야 할지 모르는 사용자입니다.

## MVP 사용자 흐름

1. 사용자가 구인 제안 텍스트와 최소한의 상황 정보를 붙여넣습니다.
2. 민감정보가 포함될 수 있다는 경고와 마스킹 안내를 봅니다.
3. 고정 규칙 엔진이 원문 구절에 근거한 `확인이 필요한 신호`를 만듭니다.
4. 각 신호를 `관찰 사실 / 공식 안내 / 앱의 제한된 추론`으로 구분해 표시합니다.
5. 사용자가 관할 국가를 선택하고 우선순위가 있는 확인 체크리스트를 만듭니다.
6. 사용자와 에이전트가 같은 화면에서 체크리스트 상태를 갱신합니다.
7. 공식 링크는 사용자가 직접 열고 판단합니다.

## 초기 WebMCP 도구 계약

도구명과 스키마는 구현 직전 최신 공식 문서로 확인합니다. 임의로 새 도구를 추가하지 않습니다.

| 도구 | 역할 | 성격 |
| --- | --- | --- |
| `get_case_summary` | 현재 사례의 마스킹된 상태 읽기 | 읽기 전용 |
| `inspect_offer_signals` | 현재 입력을 고정 규칙으로 검사하고 근거 카드 생성 | 파생 상태 변경 |
| `build_verification_plan` | 선택된 신호로 확인 체크리스트 생성 | 되돌릴 수 있는 변경 |
| `update_verification_step` | 한 단계 상태를 `todo/done`으로 변경 | 좁은 변경 |
| `get_official_resources` | 관할·주제에 맞는 허용 목록 링크 반환 | 읽기 전용 |

입력은 가능한 한 ID와 enum으로 제한하고 추가 필드를 허용하지 않습니다. 결과에는 사례 버전, 변경된 ID, 변경된 필드를 포함해 UI에서 검증할 수 있어야 합니다.

## 위험 신호 데이터 계약

```json
{
  "signalId": "UPFRONT_PAYMENT",
  "observedText": "교육비를 먼저 입금하세요",
  "observation": "업무 시작 전 금전 지급을 요구함",
  "guidanceSourceIds": ["KR-FSS-001"],
  "inference": "금전을 보내기 전에 공식 채널을 통한 별도 확인이 필요함",
  "limitations": "이 신호 하나만으로 사기 여부를 판단할 수 없음"
}
```

출처 레지스트리는 기관, 관할 국가, 자료 제목, URL, 지원하는 확인 행동, 마지막 링크 검증일, 법률 조언 여부를 보존합니다. 세부 링크와 문구는 릴리스 전에 실제로 다시 확인합니다.

## 비목표

- 범용 사기 탐지 또는 확정 판정
- 신뢰도 점수와 회사·개인 블랙리스트
- 사람, 전화번호, 회사의 자동 조사·추적
- 법률·금융 상담
- 실제 기관 신고, 메시지, 결제, 지원서 전송
- 모든 국가의 제도를 한 번에 지원
- 사용자 입력을 서버에 영구 보관하는 기능

## MVP 완료 조건

- 동일한 입력은 수동 UI와 WebMCP 호출에서 동일한 신호를 반환합니다.
- 모든 신호에 실제 입력의 근거 구절과 한계 설명이 있습니다.
- 정상처럼 보이는 사례도 `안전`으로 확정하지 않습니다.
- 공식 안내에 기관, 관할, 링크, 검증일을 표시합니다.
- 입력 속 프롬프트 인젝션 문구가 실행되지 않습니다.
- 변경 도구 호출 결과가 화면에 즉시 나타나고 사용자가 되돌릴 수 있습니다.
- WebMCP 미지원 브라우저에서도 같은 기능을 수동으로 사용할 수 있습니다.
- 자동 메시지·신고·결제 네트워크 요청이 존재하지 않습니다.
