# OfferProof 결정 기록

## D-001: 프런트엔드 우선 구조

- 상태: 승인됨
- 결정: Vite + React + TypeScript 기반의 클라이언트 우선 앱으로 시작합니다.
- 이유: WebMCP 동작을 한 페이지에서 명확히 시연하고 빠르게 정적 배포하기 위함입니다.
- 제한: 정확한 패키지 버전은 기반 프로젝트를 만들 때 lockfile로 고정합니다.

## D-002: 브라우저 로컬 처리

- 상태: 승인됨
- 결정: MVP의 구인 제안 텍스트와 분석 상태는 브라우저 안에서 처리합니다.
- 이유: 민감할 수 있는 원문을 서버에 보내지 않고 재현 가능한 시연을 만들기 위함입니다.

## D-003: 고정 규칙 우선

- 상태: 승인됨
- 결정: 위험 신호는 먼저 테스트 가능한 고정 규칙으로 구현합니다. LLM은 필수 의존성이 아닙니다.
- 이유: 같은 입력에 같은 결과를 제공하고 판정 과장을 막기 위함입니다.

## D-004: 저장소 공개 범위

- 상태: 현재 적용
- 결정: 개발 중에는 비공개를 유지합니다.
- 변경 조건: 사용자가 명시적으로 승인하고 제출 직전 최신 대회 규칙과 라이선스를 확인한 뒤 공개 여부를 결정합니다.

## D-005: WebMCP API

- 상태: 구현 전 재확인 필요
- 결정: WebMCP 등록 방식, 스키마, 브라우저 요구사항은 구현 직전에 최신 공식 문서를 확인합니다.
- 금지: 과거 예제의 API를 현재 사실로 가정하지 않습니다.
