# Offer Review 작업공간 UI·UX 명세

## 1. 목적과 설계 원칙

Offer Review는 사용자가 받은 구인 제안(Job offer)을 직접 검토하고, **확인 가능한 근거**, **공식 자료**, **제한된 해석**을 구분해 다음 행동을 결정하도록 돕는 한국어 우선 작업공간이다. 이 화면은 법적 판정, 사기 확정, 고용 결과의 예측을 제공하지 않는다. 모든 분석 결과는 사용자가 원문과 출처를 다시 확인할 수 있어야 하며, 불확실한 내용은 불확실하다고 표시한다.

기본 언어는 한국어이며, 화면의 주요 제목·버튼·오류 메시지·스크린리더 라벨도 한국어로 제공한다. `Offer Review`, `Observation`, `Official guidance`, `Limited inference`와 같이 제품에서 고정적으로 사용하는 용어는 한국어를 먼저 쓰고 괄호 안에 영어를 병기한다. 개인정보는 최소한으로 입력하도록 유도하고, 사용자가 분석 전후의 상태를 직접 통제하고 되돌릴 수 있게 한다.

> **콘텐츠 원칙:** “위험하다”라고 단정하기보다 “다음 문구가 확인을 필요로 합니다”라고 표현한다. 분석은 관찰 사실과 공식 안내를 우선 제시하고, 추론은 별도의 제한된 영역에서 가설로만 제시한다.

## 2. 정보 구조와 화면 골격

데스크톱에서는 상단 헤더, 입력 패널, 결과 패널의 2열 작업공간으로 구성한다. 입력 패널은 왼쪽에 폭 38–42%, 결과 패널은 오른쪽에 폭 58–62%를 사용하며, 결과가 생성되기 전에는 입력 패널을 넓혀 읽기와 붙여넣기에 집중시킨다. 모바일에서는 한 열로 전환하고 `① 제안 입력 → ② 개인정보 확인 → ③ 분석 결과 → ④ 검증 체크리스트 → ⑤ 공식 자료` 순서를 유지한다.

상단 헤더에는 제품명, 현재 작업 제목(기본값: “새 Offer Review”), 개인정보 안내 링크, `새 검토 시작` 버튼을 배치한다. 분석 중에는 작업 제목과 입력 내용을 유지하고, 사용자가 명시적으로 초기화할 때만 삭제한다. 결과 패널의 상단에는 분석 상태, 마지막 분석 시각, `다시 분석`, `입력 수정`, `초기화` 동작을 둔다.

| 영역 | 데스크톱 배치 | 모바일 배치 | 핵심 목적 |
|---|---|---|---|
| 입력 패널 | 좌측 고정 또는 상단 | 첫 번째 전체 폭 섹션 | 제안 원문 붙여넣기와 편집 |
| 개인정보 확인 | 입력 패널 하단 | 입력 직후 별도 섹션 | 민감정보 확인·마스킹 |
| 결과 요약 | 우측 상단 | 결과 첫 섹션 | 검토 범위와 요약 전달 |
| 위험 신호 카드 | 결과 패널 스택 | 단일 열 카드 스택 | 근거 기반 신호 확인 |
| 체크리스트 | 결과 중간 또는 우측 보조 패널 | 카드 아래 | 사용자의 직접 확인 기록 |
| 공식 자료 | 결과 하단 | 마지막 섹션 | 기관·자료의 재확인 경로 |

## 3. 구인 제안 텍스트 붙여넣기 영역

입력 영역의 제목은 **“구인 제안 원문 붙여넣기”**로 한다. 설명에는 “이메일, 메신저, PDF에서 복사한 텍스트를 붙여넣으세요. 분석 전에 개인정보를 확인할 수 있습니다.”를 표시한다. 텍스트 영역은 최소 12행(데스크톱 280px 이상, 모바일 220px 이상)으로 시작하고, 내용이 늘어나면 내부 스크롤을 제공한다. placeholder는 실제 제안처럼 보이는 민감정보를 포함하지 않고 “예: 직무, 급여, 근무지, 시작일, 담당자 안내…” 정도로만 제공한다.

텍스트 영역 아래에는 현재 글자 수와 “분석에 필요한 정보가 부족할 수 있습니다”라는 비차단형 안내를 표시한다. 짧은 입력을 오류로 취급하지 않으며, 사용자가 분석을 선택하면 부족한 정보가 무엇인지 결과에서 설명한다. 붙여넣기 직후에는 입력을 자동 제출하지 않는다. 사용자는 원문을 수정할 수 있고, `분석 시작` 버튼으로 명시적으로 분석을 시작한다.

입력 패널의 보조 동작은 다음과 같다.

| 동작 | 동작 결과 | 되돌리기 |
|---|---|---|
| `붙여넣기` | 클립보드 텍스트를 현재 커서 위치에 삽입 | 일반적인 텍스트 편집 undo 지원 |
| `입력 지우기` | 확인 대화상자 후 텍스트 제거 | 10초 동안 `되돌리기` 제공 |
| `마스킹 미리보기` | 감지된 민감정보를 화면에서 가림 | `원문 보기`로 복원 가능; 기본은 다시 마스킹 |
| `분석 시작` | 입력 상태를 보존한 채 결과 생성 시작 | `분석 취소` 후 입력 복귀 |
| `입력 수정` | 결과를 유지하고 입력 영역을 편집 상태로 전환 | `변경 취소`로 직전 분석 입력 복귀 |

분석 시작 버튼을 누르기 전, “이 텍스트를 분석하면 현재 브라우저 세션에서 결과를 표시합니다. 개인정보를 제거하거나 가린 뒤 진행하세요.”라는 확인 문구와 개인정보 확인 체크박스를 표시한다. 체크박스는 사용자가 직접 선택해야 하며, 선택하지 않았다는 이유만으로 입력을 삭제하지 않는다.

## 4. 개인정보 경고와 마스킹 안내

입력 영역과 분석 시작 버튼 사이에 항상 **“개인정보를 먼저 확인하세요”** 경고 상자를 둔다. 경고는 붉은 오류가 아니라 주의(Warning) 상태로 표시하되, 텍스트는 명확해야 한다.

> 이름, 전화번호, 이메일, 주소, 계좌번호, 주민등록번호·여권번호, 서명, 내부 직원 ID 등은 가능한 한 삭제하거나 `홍길동`, `example@example.com`, `010-****-1234`처럼 가린 뒤 검토하세요. 실제 개인정보를 입력하지 않아도 제안의 위험 신호를 검토할 수 있습니다.

자동 감지가 가능한 값은 분석 전에 마스킹 후보로 강조한다. 자동 마스킹은 원문을 파괴하지 않고 **표시용 사본**에만 적용한다. 각 후보에는 “이 부분을 개인정보로 인식했습니다”라는 설명, `마스킹 적용`, `이 항목 아님` 선택지를 제공한다. 사용자가 `원문 보기`를 선택할 때는 “민감정보가 다시 표시될 수 있습니다”를 안내하고, 원문 노출은 현재 화면에서만 일어나게 한다.

개인정보 상태는 색상만으로 표현하지 않는다. 아이콘, “확인 필요/마스킹됨/사용자 확인 완료” 텍스트, 스크린리더용 상태 문구를 함께 제공한다. 로그·분석 결과·공유 링크에는 마스킹된 값만 포함하는 것을 기본값으로 명세한다. 사용자가 개인정보를 직접 입력한 경우에도 비난하거나 분석을 중단하지 말고, 마스킹을 권고한 뒤 사용자의 선택을 존중한다.

## 5. 분석 결과와 위험 신호 카드

분석 결과 상단에는 **“검토 요약”**을 둔다. 요약은 전체 위험 점수 하나로 결론을 내리지 않고, “확인 필요 신호 3개”, “공식 자료로 재확인할 항목 2개”, “원문에서 확인된 정보”처럼 근거의 개수와 상태를 보여준다. 점수나 등급을 사용할 경우 산정 근거, 한계, “판정이 아님” 문구를 같은 영역에 배치한다.

각 위험 신호는 독립 카드로 렌더링하며 다음 순서를 고정한다.

1. **신호 제목:** 예를 들어 “선입금 요구 문구가 있습니다”.
2. **상태 배지:** `관찰 사실`, `공식 안내와 비교`, `제한된 추론` 중 하나.
3. **원문 근거:** 실제로 관찰된 문장을 짧게 인용하고, 긴 문장은 펼침 영역에서 확인한다. 근거가 없으면 카드를 생성하지 않는다.
4. **위치 정보:** 원문 문단·문장 또는 “입력 3번째 문단”처럼 사용자가 원문에서 찾을 수 있는 위치.
5. **설명:** 왜 확인이 필요한지, 무엇을 아직 알 수 없는지 설명한다.
6. **다음 확인 행동:** “계약서에서 환불 조건 확인”, “공식 기관 안내 열기” 등 사용자가 실행할 수 있는 행동.
7. **사용자 상태:** `확인 전`, `확인 중`, `확인 완료`, `해당 없음`을 선택할 수 있다.

카드의 기본 상태는 접힌 요약이 아니라 **근거가 보이는 펼침 상태**로 한다. 사용자가 `접기`를 누르면 제목·상태·근거 존재 여부가 남아야 하며, 접힘 상태도 키보드와 스크린리더로 알 수 있어야 한다. 위험 신호의 순서는 심각도만으로 정하지 않고, 근거의 명확성·사용자 행동의 시급성·공식 자료 연결 가능성을 함께 고려한다.

## 6. 관찰 사실·공식 안내·제한된 추론의 시각적 구분

세 가지 정보 유형은 **섹션, 배지, 제목, 문구, 아이콘, 색상**을 함께 사용해 구분한다. 색상은 보조 수단일 뿐이며, 색상을 제거해도 정보 유형을 식별할 수 있어야 한다.

| 유형 | 화면 라벨 | 시각 표현 | 허용 문구 | 금지 문구 |
|---|---|---|---|---|
| 관찰 사실 | `관찰 사실 (Observation)` | 중립색 테두리, 따옴표 아이콘, “원문에서 확인됨” | “원문에 ‘교육비를 먼저 납부’라고 적혀 있습니다.” | “사기입니다.” |
| 공식 안내 | `공식 안내 (Official guidance)` | 파랑 계열 테두리, 기관/문서 아이콘, 출처 링크 | “기관 안내에서는 선입금 요구 시 계약 조건을 확인하라고 안내합니다.” | 출처 없이 “법적으로 불법”이라고 단정 |
| 제한된 추론 | `제한된 추론 (Limited inference)` | 보라 또는 회색 계열 점선 테두리, 추론 아이콘, “추가 확인 필요” | “이 조합은 추가 확인이 필요한 패턴일 수 있습니다.” | “확실히 위험합니다.” |

관찰 사실은 입력 원문에서 직접 찾을 수 있는 내용만 포함한다. 공식 안내는 기관명, 자료 제목, 링크, 접근일을 함께 표시한다. 제한된 추론은 반드시 관찰 사실과 공식 안내를 선행해 보여준 뒤에 배치하며, 신뢰도·알 수 없는 정보·대안적 설명을 함께 적는다. 세 유형을 한 카드 안에서 섞지 말고, 카드 내부에도 각 유형별 하위 블록을 나눈다.

## 7. 확인 체크리스트

결과 영역에는 제목 **“확인 체크리스트”**와 설명 “아래 항목은 서비스의 판정이 아니라 사용자가 직접 확인할 질문입니다.”를 표시한다. 체크 항목 예시는 다음과 같다.

| 체크 항목 | 사용자가 확인할 대상 | 완료 시 표시 |
|---|---|---|
| 회사와 담당자 확인 | 회사 공식 도메인, 대표 연락처, 담당자 소속 | “사용자가 확인함” |
| 계약 조건 확인 | 직무, 근무지, 근무시간, 급여, 수습·환불 조건 | “계약서에서 확인함” |
| 비용 요구 확인 | 교육비, 보증금, 장비비, 송금 계좌와 환불 조건 | “비용 조건을 확인함” |
| 개인정보 요구 확인 | 요구 정보의 종류, 제출 목적, 보관 주체 | “제출 전 확인함” |
| 공식 자료 재확인 | 연결된 기관 자료의 최신 내용과 적용 범위 | “공식 자료를 읽음” |

각 항목은 체크박스와 선택적 메모 입력을 제공한다. 체크를 해도 분석 결과의 위험 등급이나 카드를 자동으로 숨기지 않는다. 사용자가 체크를 해제하면 즉시 미확인 상태로 돌아가며, 완료 수는 `3/5 확인`처럼 텍스트로도 읽을 수 있어야 한다. 체크리스트 초기화는 별도 확인 후 실행하고 10초 동안 `되돌리기`를 제공한다.

## 8. 공식 자료 영역

결과 하단에 **“공식 자료로 다시 확인하기”** 영역을 둔다. 각 자료 카드는 기관명, 자료 제목, 자료 유형, 게시·갱신일(알 수 있으면), 접근일, 이 제안과 관련된 이유, 원문 링크를 포함한다. 링크 텍스트는 “여기를 클릭” 대신 문서 제목을 사용하며, 외부 링크임을 텍스트로 표시한다.

공식 자료는 분석의 결론을 뒷받침하는 장식이 아니라 사용자가 직접 재확인하는 경로다. 링크가 열리지 않거나 자료가 갱신된 경우에는 `자료를 열 수 없음`, `최신 여부를 확인하세요`를 표시하고, 그 자료에 의존한 설명의 확실성을 낮춘다. 공식 기관으로 확인되지 않은 블로그·광고·사용자 게시물은 공식 자료 섹션에 넣지 않고 `참고 자료`로 별도 구분한다. 임의의 법률 자문이나 최신 정책을 생성하지 않으며, 지역·직종·계약 형태에 따라 적용 범위가 달라질 수 있음을 표시한다.

## 9. 화면 상태

### 9.1 빈 상태 (Empty)

처음 진입하면 결과 패널에 “아직 검토한 제안이 없습니다”를 표시하고, “구인 제안 원문을 붙여넣으면 근거와 확인 질문을 정리합니다”라는 설명과 `원문 붙여넣기` CTA를 제공한다. 위험 신호 카드, 체크리스트, 공식 자료는 빈 자리표시자나 0개 목록으로 숨긴다. 샘플 제안을 자동으로 채우지 않는다.

### 9.2 입력 상태 (Input)

텍스트 영역에 내용이 들어오면 입력 패널을 활성화하고 글자 수, 개인정보 확인, `분석 시작`을 표시한다. 개인정보 후보가 있으면 분석 시작 전 경고를 강조하되, 사용자가 내용을 수정할 수 있도록 한다. 브라우저를 새로 고침하거나 결과로 이동해도 현재 입력을 잃지 않도록 세션 내 임시 보존을 기본으로 하며, 영구 저장 여부는 별도 동의 없이는 전제하지 않는다.

### 9.3 분석 중 상태 (Analyzing)

분석 시작 후 버튼은 `분석 중…`으로 바뀌고 중복 제출을 막는다. 진행률을 실제로 측정할 수 없으면 가짜 퍼센트를 표시하지 않고, “원문을 정리하고 근거를 확인하는 중입니다”라는 상태만 제공한다. `분석 취소`는 입력을 삭제하지 않고 빈 상태가 아닌 입력 상태로 되돌린다.

### 9.4 분석 결과 상태 (Result)

결과 패널은 요약, 위험 신호, 체크리스트, 공식 자료 순서로 표시한다. 각 결과는 원문 근거를 기준으로 탐색할 수 있어야 하며, 사용자가 `입력 수정`을 선택하면 기존 결과를 “이전 분석 결과”로 보존할지 새 분석 전까지 유지할지 명확히 알려준다. 분석이 끝난 뒤에도 원문, 마스킹, 체크리스트 상태는 사용자가 수정할 수 있다.

### 9.5 오류 상태 (Error)

오류는 입력 오류, 네트워크 오류, 분석 실패, 공식 자료 링크 오류를 구분해 표시한다. 오류 제목은 원인을 추측하지 않고 “분석을 완료하지 못했습니다”처럼 말한다. 입력 내용은 유지하고, `다시 시도`, `입력 수정`, `오류 세부 정보 복사`를 제공한다. 네트워크 오류에서는 재시도 전에 원문을 다시 붙여넣게 하지 않으며, 재시도가 반복되면 사용자가 원문을 보존한 채 나중에 다시 시도할 수 있도록 안내한다. 오류 메시지는 오류가 난 입력 필드 또는 결과 영역과 연결한다.

## 10. 데스크톱·모바일 반응형 행동

데스크톱에서는 결과를 읽는 동안 입력 패널과 결과 패널의 상단 제목이 고정될 수 있으나, 화면을 가리는 고정 요소는 최소화한다. 카드의 근거와 공식 링크는 폭을 줄여도 가로 스크롤이 생기지 않도록 줄바꿈한다. 1024px 미만에서는 2열을 1열로 전환하고, 입력 패널 하단의 `분석 시작`을 화면 하단에 고정하되 키보드와 콘텐츠를 가리지 않도록 안전 여백을 둔다.

모바일에서는 붙여넣기 영역의 최소 높이를 유지하되 키보드가 열렸을 때 버튼이 가려지지 않게 한다. 긴 원문 근거는 기본 4줄 뒤 펼치기 방식으로 제공하고, 펼친 내용은 가로 스크롤 없이 단어 단위로 줄바꿈한다. 결과 카드의 액션은 작은 아이콘만 사용하지 않고 최소 44×44 CSS px의 터치 영역과 명확한 한국어 텍스트를 제공한다. 체크리스트와 공식 자료는 한 번에 하나씩 조작할 수 있도록 카드 사이에 충분한 간격을 둔다.

## 11. 접근성 및 입력 장치

접근성 구현 목표는 [WCAG 2.2의 원칙과 성공 기준][1]을 따르는 **AA 수준**이다. 명세상 필수 동작은 다음과 같다.

- 모든 입력에는 화면에 보이는 `<label>`과 고유한 접근 가능한 이름을 둔다. placeholder를 유일한 라벨로 사용하지 않는다.
- 키보드 탭 순서는 헤더, 원문 입력, 개인정보 경고와 마스킹 제어, 분석 시작, 결과 요약, 카드, 체크리스트, 공식 자료 순서로 논리적이어야 한다. 마우스 전용 드래그·호버 동작은 제공하지 않는다.
- 포커스 링은 배경과 충분히 구분되는 2px 이상의 선명한 외곽선으로 표시하고, `outline: none`으로 제거하지 않는다. 모달이 열리면 포커스를 모달 제목 또는 첫 조작 요소로 이동하고, 닫힌 뒤에는 모달을 연 버튼으로 되돌린다.
- 위험 수준·개인정보 상태·관찰/공식/추론 유형은 색상만으로 전달하지 않는다. 텍스트 라벨과 아이콘의 대체 텍스트를 함께 제공한다.
- 분석 시작, 분석 완료, 오류, 마스킹 후보 감지, 체크리스트 완료 수 변화는 적절한 `aria-live` 영역으로 알린다. 긴 결과 전체를 매번 읽지 않도록 알림은 요약 중심으로 한다.
- 접기/펼치기 버튼에는 현재 상태를 `aria-expanded`로 전달하고, 연결된 콘텐츠에는 `aria-controls`를 사용한다. 체크박스에는 항목명과 현재 상태가 스크린리더로 함께 읽혀야 한다.
- 오류 메시지는 해당 입력과 `aria-describedby` 또는 동등한 연결로 묶는다. 오류가 있는 첫 필드로 포커스를 이동하되, 사용자가 입력한 텍스트를 삭제하지 않는다.
- 본문, 배경, 버튼, 링크, 포커스 상태의 대비를 AA 기준에 맞게 검토하고, 저대비 회색 본문과 색상만으로 구분하는 배지를 사용하지 않는다. [WCAG 2.2 대비 관련 성공 기준][2]을 검수 기준으로 삼는다.
- 텍스트 확대와 화면 폭 축소 시 정보 손실 없이 재배치되어야 한다. 언어가 한국어인 문서는 `lang="ko"`로 설정하고, 영어 병기 용어는 자연스러운 읽기 순서를 유지한다.

## 12. 사용자가 되돌릴 수 있는 상태 변경

서비스는 사용자의 의도 없는 파괴적 변경을 하지 않는다. `초기화`, `입력 지우기`, `체크리스트 전체 해제`, `마스킹 후보 일괄 적용`, `원문 보기`는 동작 전후의 영향을 설명한다. 특히 마스킹은 표시용 사본에 적용하고, `마스킹 취소` 또는 개별 후보의 복원으로 사용자가 되돌릴 수 있게 한다. 입력을 삭제할 때는 확인 대화상자를 사용하며, 확인 후에도 짧은 시간 동안 실행 취소를 제공한다.

카드 접기, 체크 완료, 메모 수정은 즉시 반영하되, 사용자가 다시 클릭하거나 `되돌리기`를 통해 이전 상태로 돌아갈 수 있게 한다. 분석 결과를 새 입력으로 교체할 때는 기존 결과를 조용히 덮어쓰지 않고 “새 분석을 시작하면 현재 결과가 이전 결과로 교체됩니다”를 알린다. 취소·되돌리기·복원 동작은 키보드, 터치, 스크린리더에서 동일하게 사용할 수 있어야 한다.

## 13. 수용 기준 체크리스트

| 영역 | 수용 기준 |
|---|---|
| 입력 | 원문 붙여넣기, 편집, 글자 수, 명시적 분석 시작이 제공된다. |
| 개인정보 | 민감정보 예시와 마스킹 권고가 분석 전 보이고, 표시용 마스킹을 사용자가 검토·복원할 수 있다. |
| 근거 | 모든 위험 신호 카드에 원문 인용 또는 위치가 있고, 근거 없는 카드는 생성하지 않는다. |
| 정보 유형 | 관찰 사실, 공식 안내, 제한된 추론이 라벨·문구·구조로 색상 없이도 구분된다. |
| 체크리스트 | 항목별 확인, 해제, 메모, 완료 수 표시가 가능하며 자동 판정으로 대체되지 않는다. |
| 공식 자료 | 기관명, 제목, 링크, 접근일, 관련 이유와 링크 실패 상태가 표시된다. |
| 상태 | 빈 상태, 입력 상태, 분석 중, 결과 상태, 오류 상태의 화면과 복구 동작이 정의되어 있다. |
| 반응형 | 데스크톱 2열과 모바일 1열 전환, 긴 텍스트 줄바꿈, 모바일 CTA 접근성이 보장된다. |
| 접근성 | 키보드 순서, visible focus, 레이블, live region, 오류 연결, 색상 외 구분, 대비 검수가 포함된다. |
| 되돌리기 | 삭제·마스킹·체크 변경·결과 교체가 사용자 확인과 undo/복원 경로를 갖는다. |
| 표현 | 법적 판정·사기 확정·과도한 확률 표현을 피하고, 불확실성과 한계를 명시한다. |
